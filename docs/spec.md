# 筋トレ自己管理アプリ 仕様書

## 概要

筋トレを効果的に続けるための自己管理 Web アプリ。
実施した種目と使った筋肉を記録し、休ませるべき筋肉と使える筋肉を把握できる。設定した予定に合わせてメールで知らせ、メールから記録フォームへすぐ移動できる。

技術スタックと開発ルールは `AGENTS.md`、データベースは `docs/database-design.md` を参照。

## ゴール

- 自分がした種目などを入力し、使った筋肉と休ませるべき筋肉を把握できる
- 使える筋肉に効果的なトレーニングを提案してもらえる
- 自分が使う筋肉・時間・場所・メニューを設定し、その時間にメールで知らせてもらえる
- メールから筋トレ内容入力フォームへ移動できる
- 休息中の筋肉を使おうとしたときに確認が出て、無理なトレーニングを防げる
- 許可した人と記録を見せ合える

## 各機能の詳細

### F1 筋トレ記録の入力

- 入力項目：実行日時、メニュー、重量・回数・セット数、使用した筋肉、休憩日数
- **メニューのみ自由入力**。重量・回数・セット数は数字入力、それ以外は選択式
  - 重量は任意（自重は空欄）。0〜500kg、0.5kg 刻み
  - 回数は 1〜100、セット数は 1〜20 で必須
  - 休憩日数は 0〜7 日
- 「種目から入力」で種目を選ぶと、メニュー名・使用筋肉・休憩日数が初期値として入る
- メニュー名が種目名と完全に一致すれば、その種目の記録として扱う（自己ベストなどの対象になる）
- ダッシュボードの筋肉図で筋肉名を押すと、その筋肉の種目が入った状態でフォームが開く

### F2 休息状況の把握

- 「実行日時 + 休憩日数」が現在より後なら、その筋肉は休息中。回復予定日時も表示する
- 休息中のテーブルは作らず、記録から毎回計算する
- 記録のない筋肉は「使える筋肉」として扱う

### F3 おすすめ種目の提案

- 使える筋肉（休息中でない筋肉）を主に鍛える種目を表示する
- すべての筋肉が休息中なら、休むよう促す

### F4 休息中の筋肉の確認

- 入力フォームで休息中の筋肉が選ばれていたら、保存前に確認を表示する
- 確認には、休息中の筋肉名と回復予定日時を表示する
- 「続ける」を選ぶと保存され、「戻る」を選ぶと保存されない
- 確認なしでは保存されない（画面側だけでなくサーバー側でも保証する）
- 休息中かどうかは、入力した実行日時ではなく**現在の時刻**で判定している（実行日時を基準にするかは未決）

### F5 通知プランの設定

- ユーザーが次を設定する：**使う筋肉、日時、場所、メニュー**
- 通知のオン・オフを切り替えられる
- 通知は日付指定の1回きり（予定している日のみ）。日時は現在より後のみ
- 場所は自由入力
- 予定日時の時点で休息中の筋肉が含まれる場合は、プランを作成・更新できない
- 予定日時を変えると、送信済みでももう一度通知する

### F6・F7 メール通知とフォームへの移動

- 設定した日時になると、設定内容（日時・場所・メニュー・筋肉）をメールで送る
- プランを作った後の記録で、予定日時に休息中になった筋肉があれば、本文で知らせる
- メールには入力フォームへのボタン（リンク）がある。リンクにはプラン ID だけを入れ、パスワード・トークン・個人情報は入れない
- リンクを開くと、プランの内容（メニュー・筋肉）が入った入力フォームが開く。ここでも F4 の確認は通常どおり働く
- ログインしていなければログイン画面を経由し、ログイン後に元のページへ戻る
- 他人のプランのリンクは開けない
- 同じプランに対して二重にメールを送らない

### F8 記録の閲覧と閲覧許可

- アカウント名は常に公開（ユーザーページを開けば見える）
- それ以外（記録など）は、本人と、本人が許可したユーザーのみ閲覧できる
- 許可は、相手のメールアドレスを指定して出す。取り消しもできる。自分自身には出せない
- ユーザー一覧には、自分に閲覧を許可しているユーザーだけを表示する（#20）
- ユーザーページとマイページは同じ作りにし、本人の場合だけ入力フォームを表示する
- ユーザーページの各欄は見出しを押すと開閉する。最初に開いているのは自己ベストだけ。検索条件付きの URL や2ページ目以降を開いたときは、記録欄も開く（#19）

### F12 自己ベスト

- 種目が紐付いた記録を種目ごとにまとめ、重量 → 回数 → セット数の順に比べて一番上を自己ベストとする
- 自重（重量なし）は重量ありより下。同じ内容なら先に達成した記録を残す
- 回数を記録する前（#12 より前）の記録は対象外

### F13 記録の検索

- メニュー名（部分一致）・筋肉・期間（開始日と終了日を含む）で絞り込む。条件は組み合わせられる
- 条件は URL に残るので、戻る・共有でも同じ結果が出る
- 20件ずつページ送りする

### F14 最高重量の推移

- 種目を選ぶと、その種目の**日ごとの最高重量**を折れ線グラフで表示する
- 対象は自己ベストと同じく、種目が紐付いた記録。重量のない（自重の）記録は除く
- 横軸は日付を等間隔に並べる（日付の間隔は反映しない）
- 記録と同じく、本人と閲覧を許可されたユーザーだけが見られる

### F15 重量ランキング

- 参加者は、見る人本人と、見る人に閲覧を許可しているユーザー
- 種目ごとに、各参加者の自己ベスト（F12）の重量で並べる。自重の自己ベストは除く
- 同じ重量は同じ順位（1位, 1位, 3位）にし、先に達成した人を上に表示する
- 期間での絞り込みはない（全期間の自己ベストで比べる）
- 重量・回数・セット数をまとめた総合ランキングは作らない（合意済み）

## ページ構成

ホームページ以外はログインが必要。

| ページ | URL | 内容 | 対応する機能 |

| ダッシュボード | `/dashboard` | 全身の筋肉図。筋肉名を押すと、その筋肉の種目が入った入力フォームが開く | F1 |
| マイページ | `/mypage` | 自分のユーザーページへ移動する | ー |

| ユーザー一覧 | `/users` | 自分に閲覧を許可しているユーザーのページへのリンク一覧 | F8 |

| 設定 | `/settings/*` | プロフィール・パスワード・外観（スターターキット） | ー |

## データ

現行のデータベース設計は `docs/database-design.md` を参照。

- 休息中の筋肉のテーブルは作らず、記録から計算する（使わなくなったデータが増えるのを避けるため）
- 通知プランは専用のテーブル（`workout_plans` / `muscle_workout_plan`）に保存する

## 決定事項

- 通知の頻度 → 日付指定の1回きり
- 通知プランに休息中の筋肉が含まれる場合 → 作成・更新できない
- 「場所」の入力方式 → 自由入力
- 通知プランのテーブル設計 → `workout_plans` / `muscle_workout_plan`
- 重量・回数・セット数 → 記録ごとに1つ、`workouts` のカラムとして記録する（#12）
- タイムゾーン → 日本時間（`Asia/Tokyo`）に統一
- ランキング → 種目ごとの重量だけ。総合ランキングは作らない（#22）
